AWS data-quality pipeline

Turn an MSc cloud lab into a reproducible engineering demonstration.

The recovered coursework describes a cloud migration and S3/Lambda event workflow. Historical screenshots show an S3 upload, Lambda metrics, CloudWatch and IAM setup. This iteration adds executable validation and infrastructure as code.

Implementation

Private, encrypted, versioned input and result buckets; an event-driven Python function; narrow input/output permissions; deterministic result keys tied to object versions.

Validation evidence

Seven initial Python unit tests cover valid input, duplicate records, invalid prices, acquisition ordering, input limits, versioned repeat delivery and oversized objects. Additional release checks cover browser behavior and infrastructure schemas.

Architecture decision

Separate input and result buckets avoid output-trigger recursion. Object version IDs bind processing to the uploaded version. HTTPS delivery through CloudFront keeps the website bucket private.

Limits and next steps

The portfolio website uses its own AWS hosting stack. Recovered screenshots document the earlier MSc lab. The separate S3-to-Lambda data pipeline still requires deployment and a cloud smoke test. Demo error retries are disabled; production needs a failure queue, alarms and recovery procedures.
