Design decisions

Small components.
Explicit boundaries.

The portfolio host and the data-processing demonstration are separate stacks. That keeps a public demonstration accessible without exposing data ingestion or coupling the website to an always-on service.

Portfolio delivery

VIEWERBrowserHTTPS only after redirect
EDGECloudFrontCache + security headers
ORIGINPrivate S3Signed origin access

CloudFormation defines the origin access control, distribution and scoped bucket policy. Only the reviewed site directory is uploaded. Source archives are assembled from an explicit allowlist.

Security

Block public S3 access, enforce HTTPS, encrypt at rest and limit object permissions. The website contains no account identifiers, credentials, private documents or original screenshots.

Cost boundaries

No always-on VM, database or NAT gateway is required for the portfolio host. Free-tier eligibility and credits depend on the account. Storage, delivery, logs and requests can still incur charges; a budget alert is not a spending cap.

Recovery

Site releases are hashed and archived locally. Re-upload a retained release to roll back. S3 buckets are retained on stack deletion, so explicit cleanup is needed to stop residual storage charges.

Current limits

The browser exercise runs locally. The separate pipeline needs deployment and an integration check before it can be described as cloud-verified. Production ingestion also needs failure handling, alarms and operational ownership.
